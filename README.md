# Примитивная база данных

Домашнее задание №2 по дисциплине «Программирование на Python», группа
М26-555. Процедурное консольное приложение: функции, декораторы, замыкание
и цикл команд, без собственных классов.

Реализация подготовлена для самостоятельной проверки. Работа не сдана.
Запись демонстрации и её публикацию автор выполняет сам; ссылку на запись
нужно добавить сюда перед сдачей.

## Установка и запуск

Нужны [uv](https://docs.astral.sh/uv/getting-started/installation/) и
Python 3.12.10. Версия Python закреплена в `.python-version`, зависимости —
в `uv.lock`. Из корня проекта:

```powershell
uv sync --locked
uv run --locked database
```

Альтернативная точка входа:

```powershell
uv run --locked python -m primitive_db.main
```

Программа принимает команды до `exit`. Ctrl+C и конец ввода также
завершают её без traceback. Runtime-зависимости — `prompt` и `prettytable`;
Ruff установлен отдельно как инструмент разработки.

## Управление таблицами

```text
create_table users name:str age:int active:bool
list_tables
help
```

Удаление таблицы — `drop_table users`, выход из приложения — `exit`.
`delete` и `drop_table` запрашивают подтверждение. Только точный ответ `y`
подтверждает операцию; `Y`, пустой ввод и ответы с пробелами отменяют её.

## CRUD-операции

После создания таблицы:

```text
insert into users values ("Сергей", 28, true)
insert into users values ("Анна", 21, false)
select from users
select from users where active = true
update users set age = 29 where name = "Сергей"
delete from users where ID = 2
info users
drop_table users
exit
```

Правила данных:

- Поддерживаются `int`, `str` и `bool`. Строки вводятся в одинарных или
  двойных кавычках; логические значения — `true` и `false`.
- `ID:int` добавляется первым автоматически. При вставке передаются все
  остальные значения в порядке объявления столбцов. Новый ID равен
  максимальному существующему ID плюс один; изменить его через `update`
  нельзя.
- Число и типы значений проверяются до сохранения. Например, `true` не
  принимается вместо `int`, а `1` — вместо `bool`.
- `where` содержит одно равенство, `set` изменяет один столбец.
  Регистр имён таблиц и столбцов имеет значение.
- Пробелы, запятые, скобки и слова `where`/`set` внутри кавычек остаются
  частью строки. Python-код из значений не исполняется.

`select` выводит результат через PrettyTable. Пустая выборка сохраняет
заголовки столбцов. `info` показывает схему и количество записей.

## Хранение, декораторы и кэш

В текущем рабочем каталоге создаются `db_meta.json` со схемами таблиц
и `data/<table_name>.json` со строками. Поэтому для повторного открытия
той же базы программу нужно запускать из того же каталога. Локальные
данные исключены из Git.

Новый файл таблицы создаётся исключительно без перезаписи существующего.
Если имена `users` и `Users` обозначают один файл в текущей файловой системе,
создание второй таблицы отклоняется без изменения строк и метаданных.
Это также сохраняет файл данных, оставшийся без записи в метаданных.
При обновлении JSON сначала записывается во временный файл, затем заменяет прежний.
Повреждённый JSON считается ошибкой, а не пустой базой. Это учебное
однопользовательское приложение, без транзакций между несколькими файлами.

`handle_db_errors` выводит ожидаемые ошибки, `confirm_action` запрашивает
подтверждение удаления, `log_time` измеряет время `insert` и `select`
с помощью `time.monotonic`.

`create_cacher` хранит результаты выборок в замыкании на время запуска.
Ключ включает таблицу, схему, условие и актуальные строки. Повторная
выборка сообщает о попадании в кэш; изменение данных, в том числе внешнее,
меняет ключ. Чтение JSON при этом всё равно выполняется.

## Структура и Git

В `src/primitive_db`: `main.py` — точка входа, `engine.py` — цикл команд,
сохранение и вывод, `core.py` — таблицы и CRUD, `utils.py` — JSON,
`parser.py` — синтаксис и значения, `decorators.py` — декораторы и кэш,
`constants.py` — общие имена и справка.

Разработка ведётся по GitHub Flow в `feature/complete-primitive-db`,
с отдельными коммитами и push по этапам. Ветка `main` автоматически
не изменяется; проверка, решение о слиянии и отправка в LMS остаются автору.
